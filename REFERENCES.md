# Reference Library --- Prompting, Evaluation and Agentic Systems

**Version:** 1.0\
**Checked:** 2026-11-14

This is an initial reference set, prioritising official primary
documentation from major model providers. Provider documentation is
authoritative for that provider's products, but is not automatically
universal across models.

## Core prompting and evaluation

1.  **OpenAI --- Prompting guide**\
    https://developers.openai.com/api/docs/guides/prompting\
    Prompt construction, iterative refinement, prompt organisation and
    testing. Treat API-specific advice as API-specific.

2.  **OpenAI --- Prompt engineering guide**\
    https://developers.openai.com/api/docs/guides/prompt-engineering\
    Instruction hierarchy, structured prompts, examples, model-specific
    considerations and evaluation practices.

3.  **Anthropic --- Prompt engineering overview**\
    https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/overview\
    Establishing success criteria, testing and deciding whether prompt
    engineering is the right intervention.

4.  **Anthropic --- Prompting best practices**\
    https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/prompt-templates-and-variables\
    Clarity, examples, structured context, tool use and agentic
    patterns. Check current model-specific notes.

5.  **Google --- Gemini prompt design strategies**\
    https://ai.google.dev/gemini-api/docs/prompting-strategies\
    Prompt structure, examples, decomposition, iteration, multimodal
    prompting and grounding.

6.  **Google Cloud --- Prompt design strategies**\
    https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/prompts/prompt-design-strategies\
    Test-driven prompt design, prompt components, iterative refinement
    and evaluation.

7.  **Microsoft Learn --- Prompt engineering techniques**\
    https://learn.microsoft.com/en-us/azure/foundry/openai/concepts/prompt-engineering\
    Practical prompt design techniques and model/platform-specific
    considerations.

## How to use this library

-   Start with the provider's current official guide for the model
    actually being used.
-   Use cross-provider comparison to identify durable principles and
    model-specific differences.
-   Prefer empirical testing over claims that a particular prompt
    formula is universally optimal.
-   For advanced lessons, add relevant peer-reviewed research and
    standards references, checking publication quality and date.
-   Record the date each source is consulted because model guidance and
    product features change.

## Evidence hierarchy

1.  Peer-reviewed research, standards and reproducible empirical
    evaluations.
2.  Current official provider documentation for provider-specific
    capabilities and recommended usage.
3.  Reputable technical books, courses and practitioner research with
    transparent methodology.
4.  Practitioner blog posts, community examples and prompt collections
    as hypotheses to test, not settled facts.

## Reference maintenance

When a lesson is generated, add sources specific to its topic. Verify
links, authorship, publication/update dates and relevance. Replace
obsolete sources only with a change note; preserve useful historical
context where it explains why a practice changed.
